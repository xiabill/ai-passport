# Vibe Typeless 0.3.11

这个 Release 提供可直接使用的 macOS Bridge，以及配套的 ESP32-C3 固件。

## 本次更新

- **修复在另一台 Mac 上接管设备没反应**：设备要求新连上来的 Mac 在 3 秒内发出接管请求，而 macOS 光是发现服务和特征值就要四到六秒——请求还没发出去，设备已经先把它断掉了，看起来就是「连不上」。窗口放宽到 20 秒。保护本身没变：不主动请求的主机（旧版程序、手机、系统自动重连）仍然会被拒绝。
- **切换时两端都有提示**：设备在切断旧连接**之前**会先通知那台 Mac，所以它能明确说出「已被另一台 Mac 接管」，而不是报一个莫名其妙的断开；接管的那台 Mac 显示「已从另一台 Mac 接管」；**设备屏幕上也会显示「已切换到另一台 Mac」**，停留五秒。

## 多台 Mac 怎么用

1. 两台 Mac 都装这一版（**旧版不行**，它们还是 3 秒窗口）。
2. 设备连在 A 上时，B 的 **设置 → 连接设备** 里会看到它，状态是「另一台 Mac 在用」。
3. 在 B 上点 **「使用」**，几秒后设备就归 B 了，两台 Mac 和设备屏幕都会给出提示。

设备**不会**自动跑到别的 Mac 上：只有你点「使用」才切。

## 上一版（0.3.10）的更新

- **修复在别的 Mac 上打开提示「文件已损坏」**：打包时如果机器上没有固定签名身份（CI 就是这种情况），原来会**整个跳过签名**，结果发出去的 App 只带着可执行文件的链接器签名，应用包里没有签名资源清单。macOS 遇到这种自相矛盾的签名，报的就是「已损坏」。现在没有固定身份时也会用 ad-hoc 给整个应用包签名，并且签完立刻校验，签不成就让构建失败，不会再发出一个自己都通不过校验的包。

## 在别的 Mac 上怎么装

这个程序没有经过苹果公证，所以从网上下载后第一次打开仍会被系统拦一下（这是正常的，不是损坏）：

1. 解压后把 `FoloVibeBridge.app` 拖进「应用程序」。
2. 在访达里**按住 Control 点击**它，选「打开」，再在弹窗里选「打开」。
3. 如果系统直接拒绝、连「打开」选项都没有，去 **系统设置 → 隐私与安全性**，往下找到被拦截的提示，点「仍要打开」。

还是不行的话，在终端里执行这一行清掉下载隔离标记：

```sh
xattr -dr com.apple.quarantine /Applications/FoloVibeBridge.app
```

## 上一版（0.3.9）的更新

- **设备屏幕重做**：从四张灰卡片叠在一起，改成有层次的布局——顶栏是连接和电量，中间一块大的说明设备在干什么，下面是按键，底栏放模式和版本。空闲时中间是一个圆环加麦克风，转写时圆环变成旋转的进度弧，没连上时换成蓝牙图标；**说话时整块让位给整宽的声波和录音计时**。每张按键卡片现在把**单击、双击、长按三种用法都写出来**，不用再记。
- **一台 Mac 可以同时用多台设备**：附近空闲的 Passport 都会自动连上，拿哪台按都能说话。两台同时说话时，谁先开口就听谁的，声音不会混在一起。设置 → 连接设备里能看到扫到的所有设备和它们的状态。
- **设备可以有意地交给另一台 Mac**：设备连着的时候也会广播（放慢频率，并标明「使用中」），所以另一台 Mac 看得见它，但**不会自动抢**；在那台 Mac 上点「使用」才会切过去。随手连上来却不打招呼的主机（旧版 Bridge、手机、系统自动重连）会被设备拒绝，不会把设备偷走。
- **每台设备有自己的名字了**：以前名字取自蓝牙地址的厂商前缀，所有设备都叫 `FoloVibe-4C11`，根本分不开。现在取地址末尾，每台不同。升级后设备名会变，这是正常的。
- **按键显示名可以自己定**：设置页的按键表格里，每个手势多了一个输入框。填「讯飞」「微信」都行，设备上马上跟着变，留空恢复默认。设备字体里没有的字也能显示——文字由 Mac 画好发过去。
- **修复拔掉线之后还显示充电中**：电量计在断电后读数会持平很久，原来的判断要等到读数下降才取消。现在上涨势头消退就取消，而且拔线瞬间的电压骤降会立刻取消。

## 升级方式

从 0.3.4 或更新的版本升级不需要接线：设置页点「升级并重启」更新 Mac 程序，再点「升级固件」。**两台设备都连着的话会依次升级。**

## 上一版（0.3.8）的更新

- **修复升级完程序不见了**：点「升级并重启」之后新版本装好了，程序却没有重新打开——菜单栏和程序坞里都找不到，看上去就像消失了。负责替换的脚本原本是程序的子进程，程序一退出就被一起带走，恰好死在替换完成之后、重新打开之前。现在它独立运行，整个升级过程也会记录到 `~/Library/Logs/folovibe-update.log`，以后出问题有据可查。
- **设备上能看到固件版本**：显示在底部那行的末尾，暗灰色，不占地方。手工刷写、带未提交改动的构建会多一颗星，例如 `0.3.7*`，一眼能和正式版区分开。
- **充电时设备上有提示**：正在充电时，电量数字变绿并带一个加号，例如 `+53%`；同时底部会显示预计充满时间，例如 `充满 1:22`。电量超过 92% 之后不再显示时间——那之后充电电流会逐渐变小，按当前速度推算会明显偏乐观，与其给个不准的数字不如不给。

  设备上没有专门的充电检测线路，这个判断来自电量计读数的变化方向，所以插上之后要 20 到 40 秒才会亮起来，充电宝和充电头同样有效。

## 上一版（0.3.7）的更新

- **修复插着 USB 时闲置后失联**：芯片准备进入深度睡眠时会先把蓝牙放倒，正常情况下深度睡眠会重启芯片，这个状态自然就清掉了。但插着 USB 时芯片会拒绝入睡，于是设备继续运行，蓝牙却再也没有被放回去——不广播，也就永远连不上。现在入睡被拒绝时会把蓝牙恢复回来。

## 上一版（0.3.6）的更新

- **放下一会儿不再掉线**：闲置 5 分钟熄屏时，设备会主动断开 Mac——你去倒杯水回来它就失联了。断开之后还有第二道计时：没有连接满 60 秒就进深度睡眠，所以按键唤醒也没用，Mac 还没扫到它就又睡了，只能关机重开。现在熄屏只关屏幕，蓝牙照常工作，等到深度睡眠时间才真正睡下；未连接的窗口也放宽到 5 分钟，足够重新连上。
- **修复程序卡在「连接中」不动**：macOS 存的连接记录失效时（比如设备重启过），连接请求的回调永远不会来，而程序没有超时，于是既不扫描也不重试，一条日志都不打，只能手动重开。现在每次连接有 8 秒时限，超时就重新扫描。
- **输入法快捷键可以选单击还是双击**：以前 Typeless 固定单击、豆包固定双击，写死在代码里。输入法要求哪种只有你知道，而且会随版本变，所以改成各自可选，默认还是原来的行为。

## 上一版（0.3.5）的更新

- **任何快捷键都能绑到按键上**：动作列表之前是固定菜单，菜单以外的快捷键完全没法映射。现在选“自定义按键”，在录制框里按下想要的组合即可，`⌘C`、`F5`、`⌃⌥⇧⌘K` 都行。上、中、下三个键的单击、双击、长按共 9 个手势，每个都能单独绑。
- **修复长时间说话掉线**：连续说得久了蓝牙会自己断开。原因是音频缓冲池耗尽——每 20 毫秒的音频包都要占一个缓冲区，对方确认稍慢就会用光，而协议栈把这种情况报成链路故障。现在缓冲池扩大到三倍。
- **新增超级省电模式**：30 秒熄屏、2 分钟进深度睡眠，适合放着不动的场景。同时修好了一处浪费：深度睡眠时屏幕和电量计其实还在耗电，现在会一起断电。

## 上一版（0.3.4）的更新

- **Mac 程序可以自己升级**：启动时检查新版本，设置页点“升级并重启”即可，不用再手动下载压缩包。升级不会丢失系统授权。
- **可以在程序里升级固件**：设置页显示设备当前固件版本，有新版时点“升级固件”，通过蓝牙推送，约一到两分钟。升级失败不影响使用——校验不通过就不会切换启动分区，设备继续运行原固件。
- **再次修复重连卡住**：上一版修好了设备侧的断开时机，这次修好另一半——macOS 有时会自行恢复旧连接却不告诉程序，设备因此停止广播，而程序只顾扫描一个不再广播的设备。现在会主动接管这类连接。

## 上一版（0.3.3）的更新

- **修复睡眠后重连缓慢甚至卡死**：设备进入深度睡眠前只是“发起”断开就立刻断电，断开包根本没送到 Mac。Mac 于是一直握着一个已经不存在的连接，对唤醒后的新广播视而不见，非要等自身超时才恢复——表现就是唤醒后连不上，甚至要关机重来。现在睡前会等断开真正确认，Mac 立刻知道设备离开，唤醒后即可正常重连。

## 上一版（0.3.2）的更新

- **中键长按和双击变成换行**：发送 Option+Return 插入换行而不发送，写多行消息时不用挪手。
- **按键改成顺手的分工**：上键豆包，中键确认发送，下键 Typeless。
- **按键绑定存进设备**：断电重启后立刻显示上次的绑定，不用等 Bridge 连上。
- **界面更紧凑**：绑定改成 3×3 表格一屏看全，间距和字号整体收紧，窗口最小 880×600，窄窗口下排版不会再乱。
- **升级后不用重新授权**：新增 `create-signing-identity.sh`，用固定签名身份构建，macOS 的权限授权不再随每次升级失效。首次运行它之后再授权一次即可。
- **设备屏幕重做**：按动作分色的按键格、说话时的波形更明显、去掉了调试用的信息行。
- **设备支持串口抓屏**：社区发布需要的实时画面协议。

## 上一版（0.3.1）的更新

- **豆包终于能唤起了**：豆包的“免按模式”要求双击，而 Bridge 之前只发单次按键，并且两次按键之间没有按住停顿，豆包不认这种合成事件。现在按真实双击的节奏发送（按下、保持、松开、停顿、再来一次）。
- **默认按键改成顺手的布局**：上键管豆包，中键是确认（回车），下键管 Typeless。之前 Typeless 在中键、确认在下键，手指要跨着按。
- **设备屏幕的按键提示按上、中、下排列**，与手指位置一致（之前是中、下、上）。
- **屏幕上的方块字修好了**：字体是按源码里出现的汉字生成的子集，新增的“单击/双击/长按”等字不在其中。
- **小人不再往上飘**：跳跃动画被打断时会停在半空，而下一次又从半空起跳，于是每打断一次就永久上移几像素。现在固定从站立位置起跳。
- **录音不会被另一个输入法打断**：录 Typeless 时按豆包键（或反过来）会被忽略，而不是把当前这段掐掉。Typeless 的听写、翻译、随便问之间仍可互相切换。

## 上一版（0.3.0）的更新

- **修正中键和下键调换**：BSP 的分压电压窗口与按键枚举顺序对不上，按中键会执行下键的动作，反之亦然。上键不受影响。
- **每个键的单击、双击、长按都能自定义**：上、中、下共 9 个手势，都可以在“设置 → 硬件按键”里绑定动作。下键的双击和长按是本版新增的。改绑定不需要重刷固件。
- **回车不再抢在文字前面**：说一段长的再按发送键时，回车会等转写结果落进输入框之后才发出。
- **音频设备自动配对**：Bridge 会在系统的回环设备和 Typeless 实际能枚举到的设备之间取交集，自动选一个双方都能用的，不再写死 BlackHole。启动时如果发现自己指向的设备 Typeless 用不了，会自动跟随 Typeless 已选的设备。
- **界面重做**：左侧栏换成顶部标签栏，窄窗口下的排版错位已修复，首次设置向导只展开还没完成的步骤。

## 安装和配置 Bridge

1. 解压 `FoloVibeBridge-macos.zip`，把 `FoloVibeBridge.app` 拖到 `/Applications`。
2. 打开程序，按状态页的“首次设置向导”逐项操作，卡住的项点“一键配置”。
3. 在“系统设置 → 隐私与安全性”中给 `FoloVibe Bridge` 打开蓝牙、辅助功能和输入监控权限。
4. 安装一个虚拟回环音频设备（推荐 BlackHole 2ch），并在 Typeless 里把它选为麦克风输入。选好后回到 Bridge 点“一键配置”，Bridge 会自动对齐到同一个设备。
5. 在 Bridge 设置中选择与 Typeless 一致的基础键（`Fn` 或 `F19`）。豆包选择豆包“免按模式”使用的按键，默认是右 Option。

如果 Typeless 的麦克风列表里看不到某个已安装的回环设备，那是 Typeless（Electron）枚举不到它，换一个它能看到的设备即可 —— “一键配置”只会在两边都可用的设备里挑。

同一台 Passport 同时只接受一台 Mac。换 Mac 时，在当前 Mac 选择“释放设备给另一台 Mac”，再让另一台 Mac 上的 Bridge 自动连接。

## 按键功能

上、中、下三个键各有单击、双击、长按，共 9 个手势，都可以绑定下列动作：

| 动作 | 说明 |
| --- | --- |
| 无 | 该手势不做任何事 |
| Typeless 语音输入 / 翻译 / 随便问 | 启动对应模式；再按任意录音手势即停止 |
| 豆包语音输入 | 启动/停止豆包 |
| 发送回车 | 发送 Return；若仍在等待转写，回车会排队到文字落地之后 |
| 换行 | 插入换行但不发送 |
| 全选 / 全选并删除 | 修正刚输入的内容 |
| 自定义按键 | 发送你自己录制的快捷键，任意组合 |

默认绑定：上键单击是豆包，双击全选，长按全选并删除；中键单击发送回车，双击和长按换行；下键单击/双击/长按是听写、翻译、随便问。

选“自定义按键”后，格子下方会出现录制按钮，按下想要的组合即可，之后格子上直接显示 `⌘C` 这样的符号。设备屏幕受宽度限制，自定义按键统一显示为“自定”。

输入法快捷键那栏可以选这个键是「单击」还是「双击」——豆包的免按模式要双击，Typeless 要单击，装了别的输入法按它的要求选。

每个手势旁边还有一个输入框，填什么设备上就显示什么，留空用默认名。设备字体里没有的字也能显示，因为这些字是 Mac 画好之后发过去的。

设备屏幕上的按键提示会跟着绑定变化，所以不用记。Typeless 翻译会在基础键上追加 Shift，随便问追加 Space。

## 多台设备

附近空闲的 Passport 会全部自动连上，拿哪台按都能说话。设置 → 连接设备里能看到扫到的每一台和它的状态：空闲、已连接本机、另一台 Mac 在用。

设备正被别的 Mac 用着时，本机不会自动去抢；在这台点「使用」才会切过来。反过来也一样，所以两台 Mac 不会互相抢个不停。

两台设备同时说话时，先开口的那台占用音频通路，另一台的声音会被忽略，不会混在一起。

## 音效说明

麦克风声音通过 BLE 发送到 Mac，再写入回环音频设备供输入法使用。连接、录音开始、录音结束、编辑和发送提示音均由 Passport 设备端生成，并通过设备的 I2S → ES8311 → 硬件喇叭播放；不会改由 Mac 喇叭代播。

## 刷写固件

只刷本 Release 提供的合并固件。可以使用[在线刷机工具](https://ai-passport.folotoy.cn/tools/web-flasher/)，也可以使用 ESP-IDF 工具。固件从 `0x0` 写入：

```bash
python -m esptool --chip esp32c3 \
  -p /dev/cu.usbmodemXXXX -b 460800 \
  write_flash 0x0 FoloToy-AI-Passport-full.bin
```

已有设备不要执行 `erase-flash`。合并镜像会保留设备身份和 Recovery 保护区域。刷完后重新连接 Bridge，等待状态页显示设备已就绪。

## 常见问题

- **按键完全没反应：**多半是固件和 Bridge 版本不匹配，两端都更新到本版。
- **按键映射错位：**0.3.0 起已修正中键/下键调换；如果刷的是更早的固件会仍然错位。
- **豆包没反应：**确认豆包的“免按模式”已设好按键，并与 Bridge 里的豆包快捷键一致；0.3.1 之前的 Bridge 唤不起豆包。
- **硬件没有提示音：**重新连接设备，先测试连接提示音；仍无声时查看 Bridge 日志和设备串口日志，检查 ES8311/I2S 链路。
- **Typeless 没有声音：**确认 Typeless 的麦克风和 Bridge 的输出设备是同一个（状态页会显示是否已对齐），并确认 Bridge 已获得蓝牙权限。
- **找不到设备：**唤醒 Passport，确认它广播为 `FoloVibe-*`，测试时只保留一个 Bridge 连接。

完整的 BLE 协议、省电规则、开发构建和 Recovery 约束见[开发教程](../development/vibe-typeless.md)。
